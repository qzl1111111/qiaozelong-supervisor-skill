# Luna 教程知识笔记执行规范

## 任务目标

把教程内容整理成可以直接学习、检索、合并和交给专家智能体使用的中文专业笔记。

主要成果是 Markdown 文字笔记，不是逐页 OCR 文本、文件清单、页码审计、JSONL 样例或课程目录。笔记应像一位真正理解课程的专业学习者所写：保留重要知识，删除页眉、版权声明、广告、教师寒暄、重复目录和无知识价值的文字。

## 必须产出的文件

每个独立教程建立一个目录：

```text
<package-id>/
├── README.md                    # 教程范围、已处理文件、完成度和阅读顺序
├── notes/
│   ├── 01-主题名称.md           # 正文知识笔记；过长时继续分章
│   ├── 02-主题名称.md
│   └── ...
├── reference/
│   ├── formulas.md             # 公式、变量、单位、成立条件
│   ├── procedures.md           # 软件操作、实验/计算步骤和参数
│   ├── pitfalls.md             # 易错点、失败原因、限制和排查方法
│   └── glossary.md             # 中英文术语和缩写
├── integration/
│   ├── knowledge-index.md       # 按主题指向正文笔记，方便其他模型检索
│   └── merge-notes.md           # 与其他教程合并时记录重复、补充和冲突
└── progress.local.json          # 仅记录本地断点，不包含密码或原始全文
```

## 正文笔记的固定写法

每个知识主题使用下面的结构。没有内容的栏目不要硬填。

```markdown
# 主题名称

## 核心结论

用几段完整文字解释本主题最重要的知识，使读者不打开原教程也能理解。

## 原理与逻辑

解释为什么、各变量或步骤之间怎样关联，以及结论成立的条件。

## 公式与参数

- 写出公式；
- 定义每个变量和单位；
- 写明正负号、参考态、近似和适用条件；
- 软件参数必须说明“参数作用、推荐值或示例值、不能照搬的原因”。

## 实际做法

按顺序写清操作步骤、输入、输出和判断标准。命令、文件名、标签及代码保持原样。

## 结果如何解释

说明看到某种结果意味着什么，怎样比较，哪些结论不能从该结果直接推出。

## 易错点与限制

列出常见误用、失败原因、边界条件、不同约定和排查方法。

## 例子

只保留能帮助理解方法的短例子，改写表达，不复制大段原文。

## 与其他知识的关系

指出前置知识、可合并主题、互补内容和可能冲突的约定。
```

## 知识提炼标准

1. 必须实际读取教程内容后再写笔记，禁止只根据文件名、目录或常识生成。
2. 每一章都要回答：讲了什么、为什么、如何使用、什么时候不能用、容易错在哪里。
3. 删除逐页重复的课程名、版权声明、作者信息、页眉页脚、宣传文字和孤立页码。
4. 不复制大段原文；用自己的语言重构知识，但公式、变量、单位、命令、参数、标准术语必须准确保留。
5. 不要求在正文中保留PDF页码、幻灯片编号或视觉检查记录。只在 `progress.local.json` 记录已处理到哪个文件或章节，供断点续跑。
6. 不能识别的公式或信息写入 `pitfalls.md` 的“待人工核对”，不得猜测。
7. 同一知识在多处重复时，合并成一次完整解释；后续来源只能补充、修正或记录不同约定。
8. 不同公式、符号、参数或结论存在冲突时，分别写明各自条件，不得平均或强行统一。
9. 笔记必须有专业信息密度。只有标题、目录、泛泛总结或数条关键词不算完成。
10. 一个主题通常至少包含核心结论、原理、实际用途和限制；复杂主题应包含公式或操作细节。

## 文件类型处理

- PDF、PPT、Word：按主题或章节提炼内容，不逐页复述。
- Excel、CSV、数据文件：说明字段含义、单位、计算关系、公式、数据质量、输入输出和解释方法；不要把整张表复制进笔记。
- 脚本、Notebook：说明用途、输入、输出、依赖、关键算法、参数、执行步骤、副作用、限制和报错处理；未经授权不执行不可信脚本。
- 图片和图表：只提取图中表达的科学关系、趋势、坐标、变量和结论，不保存或复制原图。
- 加密文件：立即跳过，写入 `progress.local.json` 的 `skipped_encrypted`，然后继续其他文件；不得猜测或复用密码。

## Luna 的分批与断点规则

1. 一次只处理一个教程中的一个文件或一个逻辑章节。
2. 每完成一个主题，立即写入对应 Markdown 文件，不依赖对话记忆。
3. 每次写入后更新 `progress.local.json`，至少记录：教程、当前文件、已完成章节、下一章节、笔记文件、状态、待核对问题、加密跳过文件。
4. 已完成主题不得重新生成；再次遇到相同知识时，直接补充原主题，并在 `merge-notes.md` 记录本次新增内容。
5. 单个笔记文件建议不超过约 30,000 中文字；超过时按自然主题拆分，不按固定页数机械切分。
6. 每处理完一个源文件，检查笔记中是否包含概念、原理、公式/参数、操作、解释和限制；缺失的部分必须补齐或明确说明教程未提供。
7. 本轮如果没有新增有效知识文字，不得报告“已取得进展”。

## 完成判据

只有同时满足以下条件，某个教程才可标记完成：

- 所有可读取文件均已实际提炼，或明确记录为无专业知识/加密/损坏；
- 正文不是原始提取文本，也没有重复页眉和版权声明；
- 主要概念、公式、参数、流程、解释方法、适用条件和易错点已经进入笔记；
- `formulas.md`、`procedures.md`、`pitfalls.md`、`glossary.md` 已从正文汇总；
- `knowledge-index.md` 能把一个专业问题指向对应笔记章节；
- `progress.local.json` 中没有伪造的完成状态。

## 版权与安全

原始教程、逐字提取全文、图片、表格和密码均只留在本机。不得上传、同步、Git提交或公开发布。笔记可以完整提炼知识，但必须以独立语言重写；去掉作者名不等于自动获得发布许可。任何上传都必须由用户在另一个任务中逐文件明确批准。

## 每个教程的简短报告

只报告：教程名称、处理了哪些文件、完成了哪些知识主题、新增了哪些笔记文件、跳过的加密/损坏文件、待人工核对问题、下一步。不要在聊天中粘贴大段笔记。
